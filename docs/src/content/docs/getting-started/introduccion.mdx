openUBL es un SDK y API REST para generar, firmar y validar documentos electrónicos conformes a SUNAT (Perú). Produce XML UBL 2.1 listo para envío a la plataforma de facturación electrónica.

## Tres formas de usar openUBL

Puedes integrar openUBL según el lenguaje y la arquitectura de tu proyecto:

1. **Python nativo** — para aplicaciones Python que generan XML localmente. Usa `openubl.models`, `ContentEnricher`, `render_invoice` y `sign_ubl_xml`.
2. **API REST** — para centralizar la generación y firma en un servicio compartido. Levantas el servidor FastAPI y cualquier lenguaje puede consumirlo vía HTTP.
3. **SDK TypeScript** — para backends Node.js/Deno/Bun. Ofrece helpers tipados generados desde OpenAPI y validación runtime con Zod.

| Necesitas... | Usa |
|---|---|
| Generar XML dentro de un backend Python | Python nativo |
| Centralizar la generación/firma en un servicio | API REST |
| Type safety y autocompletado en TypeScript | SDK TypeScript |
| Llamar desde curl/Postman/otro lenguaje | API REST |

Para decidir cuál te conviene según tu escala y equipo, lee [Cómo elegir](./como-elegir/).

## Documentos soportados

| Documento | Descripción |
|-----------|-------------|
| `Invoice` | Factura electrónica |
| `CreditNote` | Nota de crédito |
| `DebitNote` | Nota de débito |
| `VoidedDocuments` | Comunicación de baja |
| `SummaryDocuments` | Resumen diario de boletas |
| `Perception` | Percepción |
| `Retention` | Retención |

## Arquitectura

openUBL se compone de tres capas:

1. **Modelos Pydantic** — Validación de datos y serialización a XML UBL 2.1.
2. **Firma digital** — Firma XAdES-EPES con certificado digital.
3. **API REST** — Endpoints tipados con FastAPI y documentación OpenAPI.

El flujo típico es: construir un modelo → renderizar a XML → firmar → enviar a SUNAT.
