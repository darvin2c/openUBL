openUBL Server aplica las reglas de validación del Excel **"Reglas de validación actualizado al 24.04.2026"** publicado por SUNAT Perú en [https://cpe.sunat.gob.pe/guias-y-manuales](https://cpe.sunat.gob.pe/guias-y-manuales).

## Fuente de verdad

- **Documento**: Excel *Reglas de validación actualizado al 24.04.2026*.
- **URL**: [https://cpe.sunat.gob.pe/guias-y-manuales](https://cpe.sunat.gob.pe/guias-y-manuales).
- **Hojas consultadas**: Factura/Boleta, Nota de Crédito, Nota de Débito, Comunicación de Baja, Resumen Diario, Percepción, Retención, Firma.

## Alcance

openUBL implementa **todas las reglas de tipo ERROR que se pueden evaluar localmente**, es decir, sin consultar padrones, listados ni servicios web de SUNAT.

La tabla inferior muestra que no quedan reglas ERROR localmente evaluables pendientes. Para el listado completo de códigos, descripciones y tests, consulta [Validaciones SUNAT detalladas](./validaciones-sunat-detallado).

Las reglas que requieren listados/padrones quedan **documentadas como fuera de alcance** en `src/openubl/validator.py`, en los módulos `src/openubl/validators/_extra_*.py` y en esta página.

## Formato de respuesta de errores

Cuando `validar_sunat=true` y el XML no cumple una o más reglas, el endpoint responde HTTP 422:

```json
{
  "detail": [
    {"code": "2074", "message": "UBLVersionID - La versión del UBL no es correcta"}
  ]
}
```

El campo `code` es el código SUNAT exacto del Excel.

## Ejemplos de errores

### Factura con UBLVersionID incorrecto

```bash
curl -X POST http://localhost:8000/api/v1/invoice/create \
  -H "Content-Type: application/json" \
  -d '{"documento": {"serie": "F001", "numero": 1, "tipoOperacion": "0101", "fechaEmision": "2019-01-01", "cliente": {"tipoDocumento": "6", "numeroDocumento": "20100198109", "nombre": "Cliente Ejemplo"}, "items": [{"descripcion": "Item 1", "cantidad": 1, "valorUnitario": 100, "precioVenta": 118, "igv": 18, "tipoAfectacionIgv": "10"}]}, "validar_sunat": true}'
```

El XML renderizado tiene `cbc:UBLVersionID=2.1` por defecto, por lo que pasa. Si se mutara a `2.0`, se devolvería `code=2074`.

### Firma con SHA-1

Si un XML firmado usa SHA-1 en `ds:SignatureMethod` o `ds:DigestMethod`, la validación post-firma devuelve `code=2089` y `code=2095`.

## Cómo verificar cobertura

```bash
# Resumen
uv run pytest -m "not e2e" -q

# Validadores extras
uv run pytest tests/_test_validator_*.py -q
```

## Convención de tests

`tests/test_validator.py` usa `@pytest.mark.parametrize` agrupado por tipo de documento. Cada entrada es `(code, mutator, expected)`:

```python
@pytest.mark.parametrize(
    "code,mutator,expected",
    [
        ("2074", lambda r: _set_text(r, "cbc:UBLVersionID", "2.0"), True),
        ...
    ],
)
```

Para agregar una regla, añade su mutator y su entrada en la tabla parametrizada.
