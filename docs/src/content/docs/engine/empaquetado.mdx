El módulo `openubl.packager` genera archivos ZIP con la estructura y nomenclatura exigidas por SUNAT para el envío de comprobantes electrónicos. Está basado en el *Manual del Programador SUNAT* (RS N° 097-2012/SUNAT).

## Convención de nombres SUNAT

Cada archivo ZIP debe seguir el formato `{RUC}-{TIPO}-{SERIE}-{NUMERO}.zip`:

| Componente | Descripción | Ejemplo |
|------------|-------------|---------|
| `RUC` | Número de RUC del emisor | `20100100100` |
| `TIPO` | Código del tipo de comprobante según SUNAT | `01` (Factura), `03` (Boleta) |
| `SERIE` | Serie del comprobante | `F001`, `B001` |
| `NUMERO` | Número correlativo del comprobante | `1`, `42` |

Para documentos de baja y resumen, el `TIPO` y la `SERIE` varían según el tipo de envío:

| Función | Patrón de nombre | Ejemplo |
|---------|------------------|---------|
| Facturas, boletas, notas | `{RUC}-{TIPO}-{SERIE}-{NUMERO}.zip` | `20100100100-01-F001-1.zip` |
| Comunicación de baja | `{RUC}-RA-{YYYYMMDD}-{NUMERO}.zip` | `20100100100-RA-20240115-1.zip` |
| Resumen diario | `{RUC}-RC-{YYYYMMDD}-{NUMERO}.zip` | `20100100100-RC-20240115-1.zip` |
| Percepción | `{RUC}-40-{SERIE}-{NUMERO}.zip` | `20100100100-40-P001-1.zip` |
| Retención | `{RUC}-20-{SERIE}-{NUMERO}.zip` | `20100100100-20-R001-1.zip` |

## Estructura interna del ZIP

Cada ZIP contiene exactamente dos entradas:

1. `dummy/` — directorio vacío requerido por SUNAT.
2. `{nombre}.xml` — el documento XML firmado.

```
20100100100-01-F001-1.zip
├── dummy/
└── 20100100100-01-F001-1.xml
```

## Funciones disponibles

| Función | Propósito | Parámetros |
|---------|-----------|------------|
| `build_filename(ruc, tipo_comprobante, serie, numero)` | Construye el nombre base SUNAT sin extensión. | `ruc: str`, `tipo_comprobante: str`, `serie: str`, `numero: int` |
| `package_invoice(xml_string, ruc, tipo_comprobante, serie, numero)` | Empaqueta una factura, boleta o nota. | `xml_string: str`, `ruc: str`, `tipo_comprobante: str`, `serie: str`, `numero: int` |
| `package_voided_documents(xml_string, ruc, fecha, numero)` | Empaqueta una comunicación de baja. | `xml_string: str`, `ruc: str`, `fecha: date`, `numero: int` |
| `package_summary_documents(xml_string, ruc, fecha, numero)` | Empaqueta un resumen diario. | `xml_string: str`, `ruc: str`, `fecha: date`, `numero: int` |
| `package_perception(xml_string, ruc, serie, numero)` | Empaqueta una percepción. | `xml_string: str`, `ruc: str`, `serie: str`, `numero: int` |
| `package_retention(xml_string, ruc, serie, numero)` | Empaqueta una retención. | `xml_string: str`, `ruc: str`, `serie: str`, `numero: int` |

## Notas

- El XML de entrada debe estar firmado digitalmente antes de empaquetarlo.
- El parámetro `numero` es un entero correlativo. La función no realiza padding; SUNAT lo espera como número decimal sin ceros a la izquierda.
- Para comunicaciones de baja y resúmenes diarios, la fecha debe ser un objeto `datetime.date` y se formatea como `YYYYMMDD`.
